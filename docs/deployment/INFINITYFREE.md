# النشر على InfinityFree

دليل خطوة بخطوة لرفع النظام على استضافة InfinityFree المجانية.

> **اقرأ ده الأول.** InfinityFree استضافة مجانية بقيود حقيقية، وبعضها بيأثر على
> Vexi Ultimate تحديدًا. القيود مشروحة بالتفصيل في [آخر الصفحة](#القيود-اللي-هتقابلك).
> باختصار: كويسة للتجربة والعرض، مش كويسة لنظام شغّال فعلاً على بيانات حقيقية.
> لو ده الاستخدام المقصود، شوف [`DEPLOY.md`](DEPLOY.md) — Render + Supabase مجاني
> برضه ومن غير القيود دي.

---

## اللي محتاجه قبل ما تبدأ

على جهازك (مش على السيرفر):

- **PHP 8.3+** و **Composer**
- **Node.js 20+** و **npm**
- برنامج FTP — [FileZilla](https://filezilla-project.org/) مجاني وبيشتغل على كل الأنظمة

الاستضافة المشتركة مفيهاش SSH ولا composer ولا npm، فكل البناء بيتم على جهازك
والناتج بيترفع جاهز.

---

## الخطوة 1 — إنشاء الحساب والدومين

1. سجّل على [infinityfree.com](https://www.infinityfree.com/) — بالإيميل بس، من غير بطاقة.
2. من لوحة التحكم اعمل **Create Account**.
3. اختار دومين فرعي مجاني (مثلاً `myerp.infinityfreeapp.com`) أو اربط دومين تملكه.
4. استنى 5–15 دقيقة لحد ما الحساب يتفعّل.

**فعّل SSL**: من لوحة التحكم → **Free SSL Certificates** → اطلب شهادة Let's Encrypt
للدومين. بتاخد 5–15 دقيقة. من غير SSL، توكن الدخول هيتبعت على HTTP مكشوف.

---

## الخطوة 2 — إنشاء قاعدة البيانات

1. لوحة التحكم → **MySQL Databases**.
2. اكتب اسم (مثلاً `erp`) واضغط **Create Database**.
3. انسخ البيانات اللي هتظهر — هتحتاجها في الخطوة اللي بعدها:

| الحقل | شكله |
|---|---|
| MySQL Hostname | `sql###.infinityfree.com` |
| MySQL Database Name | `if0_00000000_erp` |
| MySQL Username | `if0_00000000` |
| MySQL Password | نفس باسورد لوحة التحكم |

---

## الخطوة 3 — بناء المشروع على جهازك

من جذر المشروع:

```bash
./deploy/infinityfree/build.sh
```

السكربت بيعمل الآتي:

- يبني الواجهة (`npm run build`)
- يثبّت حزم الباك إند بدون حزم التطوير (`composer install --no-dev`)
- يجمّع كل حاجة في مجلد `dist-infinityfree/`
- يشيل الاختبارات والتوثيق من `vendor/` — دي بتاكل آلاف الملفات من حد الـ inode
- يطبع عدد الملفات النهائي عشان تتأكد إنك تحت الحد

الناتج بيبقى بالشكل ده:

```
dist-infinityfree/
├── index.php          ← نقطة الدخول (نسخة معدّلة)
├── .htaccess          ← التوجيه + الكاش
├── setup.php          ← تنصيب مؤقت — بيتمسح بعدين
├── index.html         ← الواجهة
├── assets/            ← ملفات الواجهة المبنية
└── erp-app/           ← ملفات Laravel (محمية بـ .htaccess)
    ├── .env.example
    ├── app/  config/  database/  routes/  storage/  vendor/ …
```

## الخطوة 4 — إعداد ملف `.env`

```bash
cp dist-infinityfree/erp-app/.env.example dist-infinityfree/erp-app/.env
```

افتحه واملا:

```env
APP_URL=https://myerp.infinityfreeapp.com
FORCE_HTTPS=true

DB_HOST=sql###.infinityfree.com
DB_DATABASE=if0_00000000_erp
DB_USERNAME=if0_00000000
DB_PASSWORD=<الباسورد بتاعك>

# نص عشوائي طويل — بيحمي setup.php
INSTALL_TOKEN=<ولّد واحد عشوائي>

CORS_ALLOWED_ORIGINS=https://myerp.infinityfreeapp.com
SANCTUM_STATEFUL_DOMAINS=myerp.infinityfreeapp.com
```

ولّد مفتاح التطبيق:

```bash
cd apps/backend && php artisan key:generate --show
```

وحط الناتج (`base64:...`) في `APP_KEY` جوه ملف `.env` اللي في `dist-infinityfree`.

ولّد توكن التنصيب:

```bash
php -r "echo bin2hex(random_bytes(24)), PHP_EOL;"
```

> **`DB_STRING_LENGTH=191` سيبه زي ما هو.** الاستضافة المجانية شغالة على
> **MySQL 5.6**، وفيه InnoDB بحد أقصى 767 بايت للمفتاح. عمود `utf8mb4` بطول 255
> بياخد 1020 بايت، يعني المايجريشن هيقف على `users.email` بخطأ
> `Specified key was too long`. الرقم 191 بياخد 764 بايت فبيعدّي.

## الخطوة 5 — الرفع بالـ FTP

بيانات الاتصال من لوحة التحكم → **FTP Accounts**:

| | |
|---|---|
| Host | `ftpupload.net` |
| Username | `if0_00000000` |
| Password | باسورد لوحة التحكم |
| Port | 21 (FTP عادي — مفيش SFTP) |

في FileZilla: اتصل، افتح مجلد **`htdocs`** على السيرفر، وارفع **محتويات**
`dist-infinityfree/` جواه (مش المجلد نفسه).

الشكل النهائي على السيرفر:

```
htdocs/
├── index.php
├── .htaccess
├── setup.php
├── index.html
├── assets/
└── erp-app/
```

> الرفع بياخد وقت — `vendor/` فيه آلاف الملفات الصغيرة. في FileZilla، من
> **Transfer → Transfer type** خلّيه **Binary**، ومن الإعدادات زوّد عدد الاتصالات
> المتزامنة لـ 4–8 عشان يخلص أسرع.

اتأكد إن `.env` و`.htaccess` اترفعوا — بعض برامج FTP بتخفي الملفات اللي بتبدأ
بنقطة. في FileZilla: **Server → Force showing hidden files**.

## الخطوة 6 — تشغيل المايجريشن

مفيش SSH، فالمايجريشن بتتشغّل من المتصفح مرة واحدة عبر `setup.php`.

افتح بالترتيب:

```
https://myerp.infinityfreeapp.com/setup.php?token=<التوكن>&action=migrate
https://myerp.infinityfreeapp.com/setup.php?token=<التوكن>&action=seed
https://myerp.infinityfreeapp.com/setup.php?token=<التوكن>&action=optimize
```

كل واحدة بترجّع نص فيه ناتج الأمر. لو ظهر `✓ تم.` يبقى تمام.

**بديل من غير `setup.php`:** شغّل المايجريشن على قاعدة MySQL محلية، اعمل export
لملف SQL، وارفعه من **phpMyAdmin** في لوحة التحكم. أبطأ بس مفيش فيه ملف خطر
على السيرفر أصلاً.

---

## الخطوة 7 — امسح `setup.php` ⚠️

من FileZilla، احذف `htdocs/setup.php`، وامسح سطر `INSTALL_TOKEN` من `.env`.

الملف ده بيقدر يمسح قاعدة البيانات كلها. سيبانه على السيرفر بعد التنصيب خطر
حقيقي مش نظري.

---

## الخطوة 8 — الدخول وتغيير الباسورد

افتح `https://myerp.infinityfreeapp.com` — المفروض تلاقي شاشة الدخول.

```
admin@erp.local / password123
```

**غيّرها فورًا** من شاشة **المستخدمين** (القائمة الجانبية → النظام → المستخدمين).

## لما تعمل تحديث بعدين

```bash
./deploy/infinityfree/build.sh
```

وبعدين ارفع بالـ FTP:

- **تغيير في الواجهة بس** → ارفع `index.html` و`assets/` بس
- **تغيير في الباك إند** → ارفع `erp-app/app/`, `config/`, `routes/`, `database/`
- **مايجريشن جديدة** → ارجّع `setup.php` مؤقتًا، شغّل `action=migrate`، وامسحه تاني
- **بعد أي تغيير في `.env` أو `config/`** → شغّل `action=clear` بعدها `action=optimize`

مش محتاج ترفع `vendor/` تاني إلا لو `composer.json` اتغيّر.

## لو حاجة مشيت غلط

| الأعراض | السبب والحل |
|---|---|
| **صفحة بيضا / خطأ 500** | افتح `erp-app/storage/logs/laravel.log` عبر FTP. أغلب الأسباب: `APP_KEY` فاضي، أو صلاحيات `storage` — خلّيها 755. |
| **كل النداءات بترجع 401 رغم إن الدخول نجح** | أباتشي بيبلع هيدر `Authorization`. اتأكد إن `.htaccess` اترفع وإن فيه سطر `RewriteRule .* - [E=HTTP_AUTHORIZATION:...]`. |
| **`Specified key was too long`** | `DB_STRING_LENGTH=191` ناقص من `.env`. ضيفه وشغّل `action=fresh` (بيمسح كل البيانات). |
| **الروابط المباشرة بترجع 404** (مثلاً `/customers`) | `.htaccess` مش موجود في `htdocs` أو `mod_rewrite` مش شغال. |
| **التطبيق بيشتغل وبعد ساعات كل النداءات بتفشل فجأة** | نظام الحماية بتاع الاستضافة — الكوكي `__test` بتنتهي بعد ~6 ساعات. النظام بيكتشف ده ويعيد تحميل الصفحة تلقائيًا. لو فضلت المشكلة، امسح كاش المتصفح. |
| **"Please wait while we verify your browser"** مكان رد الـ API | نفس المشكلة. لو حصلت باستمرار، معناها الاستضافة شدّت الحماية — مفيش حل من ناحيتنا غير النقل لاستضافة تانية. |
| **`Disk quota exceeded` أثناء الرفع** | عدّيت حد الـ 30,000 ملف. شوف القسم اللي تحت. |
| **قاعدة البيانات وقفت عن الكتابة** | عدّيت 50 ميجا. مفيش حل غير ترقية الخطة أو النقل. |

## القيود اللي هتقابلك

دي مش تحذيرات عامة — دي حاجات هتقابلها فعلاً مع Vexi Ultimate بالتحديد.

### حد الملفات: 30,000

`vendor/` بتاع Laravel لوحده بيقرب من الرقم ده. سكربت البناء بيشيل الاختبارات
والتوثيق منه، وبيطبع العدد النهائي. لو قرّبت من الحد، الحلول:

- شيل الحزم اللي مش مستخدمة من `composer.json`
- استخدم `composer install --no-dev --classmap-authoritative`

### حجم قاعدة البيانات: 50 ميجا

ده الحد الأهم لنظام محاسبي. كل عملية بتولّد قيد وسطور قيد، والجداول بتكبر بسرعة
أكبر من المتوقع. تقدير تقريبي: **حوالي 40–60 ألف قيد** قبل ما توصل للحد.
خلّي `SESSION_DRIVER=file` و`CACHE_STORE=file` (زي ما هي في القالب) عشان
ما تاكلش من المساحة دي.

### 30,000 طلب يومي

كل تحميل لصفحة بيعمل عدة نداءات API. تقريبًا **10–20 مستخدم نشط** في اليوم.
الكاش في `.htaccess` بيقلّل الطلبات على الملفات الثابتة.

### نظام الحماية بـ JavaScript

الاستضافة بتحقن صفحة تحقّق مكان أي رد لو الكوكي `__test` مش موجودة أو انتهت
(عمرها ~6 ساعات). ده معروف إنه بيكسّر نداءات الـ API في تطبيقات SPA.

عشان كده الواجهة والـ API هنا على **نفس الدومين** — بحيث الكوكي اللي المتصفح
أخدها وقت تحميل الصفحة تتبعت مع نداءات الـ API. وكمان الواجهة بتكتشف صفحة
التحقّق لو ظهرت وبتعيد تحميل الصفحة مرة واحدة عشان الكوكي تتجدد
(`apps/frontend/src/lib/api.ts`).

النظام ده بيقلّل المشكلة، بس **مش بيلغيها**. أي حاجة تنادي الـ API من غير متصفح
(تطبيق موبايل، تكامل خارجي، webhook) مش هتشتغل خالص.

### مفيش اتصالات خارجية

الاستضافة المجانية بتحجب الاتصالات الصادرة من PHP. يعني:

- **SMTP مش هيشتغل** — الإيميلات مش هتتبعت (`MAIL_MAILER=log`)
- أي تكامل خارجي مستقبلي (بوابة دفع، ZATCA API للمرحلة الثانية) مش هيشتغل

### مفيش cron

الخطة المجانية مفيهاش مهام مجدولة، فـ `QUEUE_CONNECTION=sync` — كل حاجة بتتنفذ
فورًا داخل الطلب نفسه. مناسب للحجم ده.

### MySQL 5.6

إصدار قديم (2013). النظام متوافق معاه بعد ضبط `DB_STRING_LENGTH=191`، ومفيش
أعمدة `JSON` في المايجريشن فمفيش مشكلة تانية. بس خد بالك إن أي مايجريشن جديدة
تضيف عمود `json()` مش هتشتغل عليه.

لو النظام بقى شغّال فعلاً على بيانات حقيقية:

| المشكلة | البديل |
|---|---|
| القاعدة عدّت 50 ميجا | **Supabase** (PostgreSQL, 500 ميجا مجانًا) — الإعداد جاهز في المشروع |

| عايز تفضل على استضافة مشتركة | أي استضافة PHP مدفوعة رخيصة — نفس الخطوات دي بالظبط، من غير قيود الحماية والاتصالات |
