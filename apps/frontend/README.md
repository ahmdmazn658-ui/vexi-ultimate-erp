# ERP Frontend — لوحة الإدارة

واجهة React للـ Laravel API، عربية بالكامل مع دعم RTL أصلي.

## الستاك

| الأداة | الإصدار | ليه |
|---|---|---|
| React | 19.2 | أحدث major مستقر |
| Vite | 8 | بناء وتطوير سريع (Rolldown) |
| TypeScript | 7 | النسخة الأصلية المكتوبة بـ Go — أسرع بكتير في type-checking |
| Tailwind CSS | 4 | التخصيص في CSS مباشرة عبر `@theme` — مفيش `tailwind.config.js` |
| TanStack Query | 5 | إدارة حالة السيرفر، caching، وinvalidation تلقائي |
| React Router | 8 | التوجيه (لاحظ: `react-router` مباشرة، `react-router-dom` اتوقف عند 7.x) |
| Recharts | 3 | الرسوم البيانية |

## التشغيل

```bash
cd apps/frontend
npm install
npm run dev      # http://localhost:5173
```

الـ dev server بيعمل proxy لكل `/api` على `http://localhost:8000` (الـ Laravel backend). لو الباك إند على عنوان تاني:

```bash
VITE_API_TARGET=http://localhost:9000 npm run dev
```

للإنتاج، حدّد العنوان في `.env`:

```
VITE_API_BASE_URL=https://api.example.com
```

```bash
npm run build     # tsc -b && vite build → dist/
npm run preview   # معاينة نسخة الإنتاج محلياً
```

> بيانات الدخول بعد `php artisan db:seed`: `admin@erp.local` / `password123`.

## الشاشات

٢٩ شاشة. الشاشات المكتوبة بإيد فيها منطق مش متكرر (رسوم، تخصيص مبالغ، إقفال)،
والباقي متولّد من تعريف — شوف قسم "طبقة الموارد" تحت.

### مكتوبة بإيد

| المسار | الشاشة | الـ endpoints |
|---|---|---|
| `/login` | تسجيل الدخول | `POST /auth/login` |
| `/` | لوحة المؤشرات — KPIs، اتجاه مبيعات 12 شهر، أعلى العملاء | `GET /dashboards/summary` |
| `/invoices` | فواتير المبيعات: إنشاء ببنود متعددة + الإصدار | `GET/POST /e-invoicing/invoices`, `POST .../{id}/issue` |
| `/payments` | سندات القبض والصرف + تخصيص على فواتير + إلغاء | `GET/POST /finance/payments`, `POST .../{id}/void` |
| `/reports` | ميزان مراجعة، قائمة دخل، مركز مالي، أعمار الذمم | `GET /reports/*` |
| `/periods` | الفترات المحاسبية: إنشاء، إقفال، إعادة فتح، الإقفال السنوي | `GET/POST /accounting/periods/*` |

### متولّدة من تعريف

| المجموعة | الشاشات |
|---|---|
| المالية | فواتير الموردين (إنشاء + اعتماد) |
| المحاسبة | شجرة الحسابات، القيود اليومية (سطور + ترحيل)، الموازنات، الحسابات البنكية، الحركات البنكية (تسوية) |
| المبيعات | العملاء، طلبات البيع (تأكيد بيخصم من المخزون)، العملاء المحتملين (تحويل)، الفرص (نقل مرحلة)، تذاكر الدعم |
| المشتريات والمخزون | الموردين، أوامر الشراء، المستودعات، المنتجات، حركات المخزون، قوائم المواد، أوامر الإنتاج (بدء/إنهاء) |
| المشاريع والأصول | المشاريع، العقود، العقارات، تفتيشات الجودة، الأصول الثابتة (تشغيل إهلاك) |
| الموارد البشرية | الموظفين، دورات الرواتب (ترحيل)، الوظائف الشاغرة، المتقدمين (تعيين) |
| النظام | المستندات (رفع/تحميل)، المستخدمين |

## طبقة الموارد

معظم الموديولات بتتكلم نفس اللغة: `GET` بترجّع paginator، `POST` بتنشئ،
`PUT /{id}` بتعدّل، `DELETE /{id}` بتحذف، وأي عملية إضافية بتبقى `POST` على
مسار فرعي. بدل ما نكرر نفس الكود ٢٤ مرة، الشاشات دي متولّدة من تعريف.

إضافة موديول جديد = ملف تعريف واحد + سطر في `resources/index.ts`:

```ts
export const warehouses: Resource = {
  slug: 'warehouses',                    // بيبقى المسار كمان: /warehouses
  title: 'المستودعات',
  endpoint: '/inventory/warehouses',
  create: true, edit: true, remove: true, searchable: true,
  columns: [
    { key: 'code', label: 'الكود', format: 'code' },
    { key: 'name', label: 'الاسم' },
    { key: 'is_active', label: 'الحالة', format: 'bool' },
  ],
  fields: [
    { name: 'code', label: 'كود المستودع', required: true, only: 'create' },
    { name: 'name', label: 'الاسم', required: true },
  ],
}
```

- `only: 'create' | 'edit'` بيطابق اختلاف التحقق بين `store` و`update` في الكنترولر.
- `kind: 'ref'` + `ref: 'products'` بيولّد قائمة اختيار بتقرا من endpoint تاني وبتتكاش.
- `actions` للعمليات الخاصة (ترحيل، اعتماد، تعيين)، ولو العملية محتاجة مدخلات
  بتحط `fields` جواها وبتتفتح نافذة صغيرة.
- `items` لمحرّر البنود (فواتير، أوامر شراء، سطور القيد).

## ملاحظات تنفيذية

**المصادقة.** التوكن (Sanctum) بيتخزن في `localStorage` وبيتضاف تلقائياً في كل request عبر interceptor. أي استجابة `401` بتنضّف الجلسة وترجّع لصفحة الدخول.

**تحديث البيانات.** أي عملية بتأثر على المحاسبة (ترحيل سند، إصدار فاتورة، اعتماد فاتورة مورد) بتعمل invalidate للفواتير والتقارير واللوحة مع بعض — فالأرقام على الشاشة ما تسبقش الدفاتر.

**RTL.** الاتجاه متظبط على `<html dir="rtl">` وTailwind بيتعامل معاه تلقائياً. الأرقام والتواريخ والحقول اللاتينية متعلّم عليها `dir="ltr"` أو كلاس `.num` عشان ما تتلخبطش في النص العربي.

**تقسيم الحزمة.** الصفحات بتتحمّل بـ `lazy()`، فـ recharts (أتقل مكتبة) ما بيتحملش غير لما تفتح اللوحة. الحزمة الأولية ~117 kB مضغوطة.
